# 自测工具（静态分析 + 动态遍历）

改完代码后**跑一遍这两个方向**，是发现"崩溃 / 功能失灵 / 逻辑错误"最有效的方式。
上次那个"打开 Edge 就崩溃退出、日志还空白"的问题，就是动态遍历抓出来的。

## 怎么跑

**最简单**：双击项目根目录的 **`自测.bat`**，报告会输出到 `tests\自测报告.txt`。

**单独跑某一项**：

```powershell
python tests\check_static.py     # 静态分析
python tests\check_dynamic.py    # 动态遍历压测
python tests\check_startup.py    # 启动性能 + 启动瞬间朝向
python tests\check_sound.py      # 音效系统
```

## 各项检查什么

| 脚本 | 覆盖内容 |
|---|---|
| `check_static.py` | ① 语法编译 ② **pyflakes**（未定义变量、重复定义、未使用变量）③ **AST 扫描**（注释里被吞掉的赋值语句、函数内未定义变量、超长函数提示）。不需要 Qt，纯文本分析 |
| `check_dynamic.py` | 遍历面板**每一个按钮/复选框/滑块/下拉/输入框/列表项**，再模拟日常操作：连点、长按、拖拽、右键、弹射（含边缘反弹）、喂食文件与目录、跟随/躲避/漫游/锁定/置顶五种模式 tick、表情与大小全量切换、台词与气泡全量切换、音效播放、应用监控触发、日志清理。**任何被异常保护记录的异常都会打印出来** |
| `check_ui.py` | **UI 完整性**：① 每页各控件文字是否被截断（按字体度量比对宽度）② 控件是否被禁用 ③ **像素级边缘检测**：抓图后检查卡片内容区底边/右侧是否出现"控件色"（能自动发现内容被裁/贴边）④ **交互有效性**：6 个滑块、6 个复选框、下拉框、+520W 按钮改动后配置是否真的生效 ⑤ 各页高度是否随内容自适应 |
| `check_panel_layout.py` | 高 DPI 修复是否存在、各页高度自适应、拖动中恢复方形（不变形/重影）、拖动方向正确 |
| `check_hud.py` | HUD 两行竖排（Token 一行、日期时间一行）、只时间 / 只 Token、日期可单关、按秒刷新、字号 15~24px、全关隐藏收缩、点击不误触 |
| `check_app_monitor.py` | 应用监控：冷却默认 0（每次触发）、冷却可调、按规则内容记录、标题兜底匹配、气泡关闭写日志、概率未命中写日志、规则文件自动重载、停留不刷屏 |
| `check_monitor.py` | 崩溃回归（规则命中不再退出）、回调异常被记录、日志按 7 天/100 份清理 |
| `check_startup.py` | 启动分段耗时、启动到可见总时长、**启动瞬间朝向**（贴左边缘应立即镜像）、音效延迟预加载、耗时日志 |
| `check_sound.py` | 音效目录扫描、播放器池"每声完整播放"、池满接管最早、预加载不重复、自定义音效覆盖、音量同步 |
| `check_fullscreen.py` | **全屏判定**：纯函数用例（真全屏 / 桌面 Progman·WorkerW / 任务栏 / 最大化浏览器 / 半屏 / 最小化 / 采集失败）+ 同屏判定（副屏全屏不该藏主屏桌宠）+ 桌宠集成（前台是桌面不隐藏、真全屏才隐藏）+ 隐藏/恢复时序（2 次防抖、恢复立即、关开关立刻恢复、250ms 轮询） |
| `check_perf.py` | **性能专项**：静止时移动节拍降频、开启跟随/漫游立刻回 60fps、静止 tick 开销、全屏隐藏期间 HUD/移动/眨眼/轮换全部暂停（前台轮询保留）、进程名按 PID 缓存、镜像位图缓存命中与失效、设置面板关闭后悬停轮询停止 |
| `check_regression.py` | 回归专项：屏幕外坐标兜底、面板尺寸受控、拖动时自动移动让位、拖动中 HUD 布局冻结、漫游贴边卡住自恢复 |
| `diag_panel_fit.py` / `diag_monitor.py` / `diag_perf.py` | 诊断工具：面板各页尺寸与裁切排查、应用监控"为什么没触发"逐场景复现、**性能热点微观基准**（镜像位图 / 进程名查询 / 空转 tick / 全屏隐藏，只出数字不做断言） |

> 说明：`check_ui.py` 的控件几何检查受 Qt 布局刷新时机影响，因此以**文字截断 + 边缘像素 + 交互有效性**这三类判据为准（最稳、最能反映真实观感）。

## 结果怎么看

- `[OK]` / `ALL OK`：通过
- `[WARN] n 条`：需要人工判断（例如 AST 的"超长函数"提示属于可维护性建议）
- `发现异常（应修复）` + 堆栈：**必须修复**，那是真实 bug
- 末尾 `进程存活: True`：说明整个过程没有把程序搞崩

## 为什么这两条路都要走

- **静态分析**能发现"代码根本没被执行到"的问题：未定义变量、写错的属性名、被注释吞掉的语句（上次崩溃的元凶）
- **动态遍历**能发现"代码跑起来才炸"的问题：Qt 参数不匹配、空数据、状态组合、弹窗回调……
  两条路互补，缺一个都会漏。
